# 7记账

一个运行在 iPhone 上的记账 App：原生 SwiftUI，延续 iOS 27 液态玻璃风格（最低 iOS 26），支持 iOS 27 授权自动识屏会话、银行短信自动化、截图识别、灵动岛、多银行卡余额管理、iCloud 同步。

重点解决两件事：**不多记**（跨渠道自动去重、转账/退款不入账）、**不漏记**（信息不全时标「待确认」而不是丢弃）。

---

## 功能

| 模块 | 说明 |
|---|---|
| 自动记账 | 银行消费短信通过「快捷指令」自动化触发；邮件需确认可传正文，剪贴板需先复制 |
| iOS 27 自动识屏 | 先通过系统界面开启一次，会话中自动识别成功支付页，无需每笔按键；跨 App 后台行为待真机验收 |
| 手动记账 | 侧边按钮一键截图识别、轻点背面、App 内粘贴 / 截图 OCR |
| 解析引擎 | 微信支付、支付宝、花呗、余额宝、银行短信、手机银行、截图 OCR 文本 |
| 截图识别 | 方向修正、自适应视觉行、多行字段、困难图片增强重试；商户与商品分别保存 |
| 新截图自动化 | 手动截屏后退出支付 App，自动识别90秒内的新截图，需提前授权相册 |
| 去重 | 同一笔消费多渠道来消息只记一次；手动与自动之间也会合并 |
| 余额 | 微信余额 / 支付宝余额 / 多张银行卡（精确到卡号），信贷不计入 |
| 统计 | 日 / 周 / 月 / 年，趋势曲线、分类排行、文字小结 |
| 灵动岛 | 紧凑显示金额，展开显示金额/分类/商户/余额/时间，锁屏完整卡片 |
| iCloud 备份 | 选一个 iCloud Drive 文件夹，自动上传，换机自动合并恢复 |

## 为什么不能直接读微信通知

iOS 没有读取其他 App 通知或订阅微信/支付宝个人支付结果的通用入口。**iOS 27 可使用 ScreenCaptureKit，在用户通过系统界面明确授权后，持续获取屏幕帧并在本机识别支付页。** 本版已实现该会话入口，系统共享状态可见、不会静默自动开启。使用步骤及官方依据见 [自动记账方案调研](docs/automatic-bookkeeping.md)。

| 通道 | 覆盖场景 | 需要设置 |
|---|---|---|
| iOS 27 自动识屏会话 | 用户授权后，自动读取显示在屏幕上的成功支付页 | 每次会话需通过系统界面开启；停止或锁屏后重新授权开启 |
| 银行短信自动化 | 银行确实发送消费短信的绑卡支付、刷卡 | 一次性；注意提醒门槛和关键词 |
| 银行邮件自动化 | 银行提供逐笔邮件且自动化可传正文 | 需银行支持，并在真机验证输入内容 |
| 剪贴板辅助 | 手动复制账单后入账 | 需每次先复制本次账单 |
| 侧边按钮截图识别 | 微信零钱、支付宝余额等所有场景 | 一次性（2 个动作） |
| 截屏后退出即记账 | 先手动截取支付页，再退出微信/支付宝 | 相册授权 + App 关闭自动化 |

绑卡消费是否发短信取决于银行、卡种、金额门槛和提醒服务。零钱、余额、部分信贷消费不能依靠银行短信覆盖。App 关闭自动化本身不知道是否付款，也不能截取退出前的页面。

## 快捷指令

`tools/make_shortcuts.py` 可生成四个快捷指令文件（不入库，本地生成）：

```bash
python3 tools/make_shortcuts.py
```

| 文件 | 用途 |
|---|---|
| 侧边按钮 | 截屏 → 识别截图记账（设为「操作按钮」即可） |
| 剪贴板记账 | 读剪贴板 → 自动记账 |
| 账单文本记账 | 接收文本输入 → 解析记账（用于「信息」「电子邮件」自动化） |
| 新截图自动记账 | 读取90秒内的新截图 → 识别记账（用于支付 App「关闭时」自动化） |

生成的是实验性未签名源文件。本次在当前 macOS 上执行 `shortcuts sign` 返回格式错误，因此 Release 不提供声称可直接导入的文件；请按 App 内说明，在 iPhone 动作库直接添加“7记账”的动作。自动识屏会话无需快捷指令。

> 「个人自动化」的触发器（收到短信 / 邮件 / App 关闭）无法通过文件分享，只能在手机上新建一次，
> 可直接在动作库搜索“7记账”，选择对应动作。

## 安装

1. 从 [Releases](https://github.com/callum-albert/7_Bookkeeping/releases) 下载 `7jizhang.ipa`
   （GitHub 会过滤 Release 资产名里的非 ASCII 字符，所以文件名用拼音，App 显示名仍是「7记账」）
2. 用 SideStore / AltStore / 自有开发者证书签名安装
3. 主 App 与 `PlugIns/SevenWidgets.appex` 都需要签名（多数工具会自动递归）
4. 系统要求：iOS 26.0+

> 仓库中的 IPA 为 **ad-hoc 签名**，仅作为结构完整的占位，真机安装前需要用自己的证书重签。

## 从源码构建

构建不依赖 Xcode，只需要 macOS 命令行工具（含 Swift 6.4+）。

```bash
# 1) 下载 iOS SDK（约 53MB，脚本会自动分段加速下载）
./tools/fetch_sdk.sh

# 2) 构建
./build.sh
# 产物：7记账.ipa
```

构建脚本会：

- 编译主程序与灵动岛扩展（`arm64-apple-ios26.0`）
- 生成本地图标（`tools/make_icon.py`，优先使用 `tools/icon-source.png`）
- 写入 Info.plist、本地化名称
- ad-hoc 签名并打包 IPA

### 关于宏

Swift 6 起 `@State` / `@Binding` / `@Environment` 等是**宏**，需要 Xcode 随附的宏插件库，纯命令行环境里没有。本项目把它们展开成等价的属性包装器写法：

```swift
// 宏写法
@State private var count = 0

// 本项目写法（等价）
private var _count = State(wrappedValue: 0)
private var count: Int { get { _count.wrappedValue } nonmutating set { _count.wrappedValue = newValue } }
```

因此无需 Xcode 即可编译，运行时行为与原生一致。`@Observable` 使用了命令行工具自带的 Observation 宏插件，可正常使用。

## 去重规则

自动触发（短信/邮件/剪贴板）合并窗口 5 分钟；手动触发（侧边栏按钮/截图）30 分钟。

| 场景 | 结果 |
|---|---|
| 银行短信已记 → 按按钮截图 | 合并，补上商户名 |
| 按按钮记 → 银行短信后到 | 合并，补上卡尾号 |
| 连按两次按钮 | 只记一次 |
| 同金额、不同商户、都有商户名 | 两笔真实消费，都保留 |
| 提现 / 充值 / 还款 / 收款 / 退款 | 不入账，记入「已忽略」供复核 |

## 项目结构

```
Sources/
  App/            App 入口、URL Scheme
  Model/          数据模型、余额账户、本地存储、去重引擎、同步快照、统计
  Parser/         账单文本解析（微信 / 支付宝 / 银行短信 / OCR）
  Services/       自动记账调度、OCR、iCloud 备份
  Intents/        App Intents（快捷指令 / Siri / 操作按钮）
  LiveActivity/   实时活动数据与控制器
  Views/          首页、统计、记一笔、设置、余额管理、引导页
  Widget/         灵动岛 / 锁屏实时活动 UI
tools/            图标生成、解析测试、SDK 获取
build.sh          一键构建
```

## 测试

解析 / OCR 几何版式 / 去重 / 余额 / 同步 / 旧数据兼容回归：

```bash
bash tools/test.sh
```

另外提供真实图片验收工具，与 App 复用同一个 `ReceiptOCR` 图像管线：

```bash
bash tools/test_images.sh --output /tmp/ocr-results.json \
  --expected /tmp/expected.json /path/to/private-receipt.HEIC
```

期望 JSON 格式见 [OCRImageTests.swift](tools/OCRImageTests.swift)。原图、期望值和含账单内容的结果均应放在仓库外。本次8张真实微信账单图、72项字段匹配全部通过；这组样本不包含支付宝原图，不能据此声称支付宝或任意截图100%准确。分类按现有规则及样本可见信息验收。

已完成 iOS 编译、弱链接兼容检查和主程序/扩展签名校验。自动识屏的系统授权、跨 App 后台运行、锁屏停止及耗电仍需 iPhone 真机验收；当前验证不等于真机端到端通过。账单图像在本机处理，不上传云端识别。
