# 7记账

原生 SwiftUI iPhone 记账 App，保留 iOS 27 液态玻璃界面，最低支持 iOS 26。当前版本支持支出、收入、退款、自定义分类、多银行卡余额、灵动岛与 iCloud 同步。

## 记账方式

- **自动记账只保留银行短信**：配置快捷指令「信息」自动化，把消费、入账、退款短信正文交给「解析账单文本记账」。银行需确实发送提醒；不同措辞可分别设置规则。
- **手动按键记账**：快捷指令使用「截屏」→「Base64 编码」→「7记账 · 用编码截图记账」，把编码结果接到「编码截图」。App 还原原图后使用内置 Vision 识别，不走相册或剪贴板。
- **App 内手动**：记一笔时选择收入或支出、分类、收支账户；保留用户主动点击的粘贴识别和截图识别。

已移除银行邮件、自动剪贴板、截屏后退出自动记账及实验性识屏会话。App 回到前台不再自动读取剪贴板。

## 收入、退款和余额

银行卡入账可自动记录为收入；微信/支付宝收款和红包可用按键截图补记。消费退款单独记录为收入，默认分类明确标注「退款」。自己账户之间的转移仍不计收支，原有花呗还款分类规则保持兼容。

两种记账入口都识别付款/收款账户的银行与卡尾号，并在新增、合并和判重路径添加新卡；升级时也会从已有账目补登记银行卡。不同银行的同尾号卡保持独立，不把收单机构当作付款银行。账单只显示末四位时，只能识别尾号，不能恢复完整卡号。新卡余额仍需设置，短信中明确提供账户余额时可校准。

收入与支出分别统计；收入增加已识别账户余额，删除收入撤回对应增加。手工录入选择「不指定账户」时只记收支、不调整余额。退款至信用卡不会当作储蓄卡现金余额增加。

## 本人账户流转与余额核对（v1.5.0）

余额页不再显示固定的核对或转账入口。仅在余额与账单不一致、余额为负或有资金流动无法匹配到账户时显示异常提示；从提示中进入核对和处理流程。明确账户、交易单号且无手续费歧义的提现/充值仍可自动调整两端余额。内部流转不计收支，手续费单独留存在流转记录中。

新增余额与账单核对：首次升级以现有余额建立基准，运行期间每分钟及返回前台时检查差异。发现异常后先核对真实余额和账单，再手动修改并确认新基准；不推测历史期初余额，不承诺杀后台后持续检查。

v1.5.1 取消账单确认机制：自动识别后直接入账，不显示待确认数量、标签和确认按钮；旧数据及旧备份中的确认状态自动清除，仍可手动修改账目。OCR 内部置信度判断继续用于识别重试，不产生用户确认任务。详见 [v1.5.1 更新说明](docs/releases/v1.5.1.md)。后台执行限制与真机验收清单见 [v1.5.0 说明](docs/releases/v1.5.0.md)。

## 自定义分类

「我的 → 自定义分类」、记一笔的分类区和详情分类菜单均可管理自定义收入/支出分类。可添加、删除，同类型不能重名。删除后不再用于新账目，历史名称和统计保留；同步删除记录防止旧备份复活已删分类。

## 去重

- 同平台、同交易单号、同收支方向的重复识别只保留一笔；再次识别可补全商户、商品或卡信息，不重复更新余额。
- 同店、同金额但交易单号不同，或明确支付时间不同的两笔消费分别保留。
- 原消费与退款分别作为支出和收入，不互相吞掉。
- 银行短信和手动截图可合并；一般自动合并窗口5分钟，手动30分钟。没有单号、商户或精确时间时只能保守推断，不能保证区分所有同额交易。

## 安装与 SideStore

从 [Releases](https://github.com/callum-albert/7_Bookkeeping/releases) 的 **Assets** 下载 `7jizhang-<版本号>.ipa`（例如 `7jizhang-1.5.0.ipa`），不要导入 Source code.zip。主 App 与灵动岛扩展都需要重新签名；发布包为 ad-hoc 构建，安装前仍需自己的开发者签名或支持的侧载工具。

新版用最基础的 ZIP Stored（不压缩）格式打包，避免依赖侧载工具的 deflate 解码路径。构建时逐项检查 ZIP 本地头、中央目录、CRC、可执行文件和 Bundle Identifier，并对主程序和扩展做严格签名校验。包较旧版更大属正常现象。

针对之前的「Archive appears to be corrupt」：旧版与新版原始发布包均通过本机 CRC 检查，尚未取得用户设备上的失败文件或完整错误日志，无法据此确认唯一原因；新的打包方式已通过本机校验，但不能冒称 SideStore 真机安装已通过。Release 同时提供 SHA256 校验文件。

## 构建与验证

```bash
./tools/fetch_sdk.sh   # 没有本机 iOS SDK 时使用
./build.sh
bash tools/test.sh
```

输出 `build/7jizhang-<版本号>.ipa` 和工作区根目录的 `7记账-<版本号>.ipa`。在本机临时目录完成编译、签名与打包，避免 iCloud 给 .app 添加扩展属性造成签名失败。

真实图片验收与 App 复用相同 OCR 管线：

```bash
bash tools/test_images.sh --output /tmp/results.json \
  --expected /tmp/expected.json /path/to/private-receipt.HEIC
python3 tools/verify_ipa.py build/7jizhang-1.5.0.ipa
```

原来的8张真实微信账单图仍保持8/8图片、72/72字段匹配。收入、退款、自定义分类和新卡登记另外做模拟文本及存储回归；未获得真实收入/退款原图，不能声称其图片准确率100%。图片、期望值、私人报告均不提交公开仓库。iPhone 布局及 SideStore 实际安装仍需设备验收。
