# 银行短信和手动按键记账

> v1.5.1 取消账单确认机制，余额核对与转账处理仅在异常提示中提供入口，见 [v1.5.1 说明](releases/v1.5.1.md)。后台限制与真机验收清单见 [v1.5.0 说明](releases/v1.5.0.md)。定时核对仅在 App 运行时和回到前台执行，不承诺强制杀后台后常驻工作。

当前版本只保留银行短信自动记账。银行邮件、自动剪贴板、截屏后退出自动记账和实验性识屏会话已移除。

## 银行短信

1. 先确认银行向当前手机号发送逐笔消费、入账及退款提醒，并了解金额门槛。
2. 快捷指令 → 自动化 → 信息，选择银行发件号码。按实际措辞分别建立「消费」「支出」「入账」「收入」「退款」等规则，选立即运行。
3. 添加「7记账 → 解析账单文本记账」，把收到的信息正文传给账单文本。不能只传发件人。
4. 解锁运行一次完成系统授权，用真实短信核对结果。没有收到银行短信的交易不会触发。

银行卡入账短信记收入；退款记收入并标注退款。本人账户之间的转移不计收支。银行未提供商户或完整时间时，账目可能需要核对。

## 手动按键

1. 新建快捷指令：「截屏」→「Base64 编码」→「7记账 · 用编码截图记账」。把第三步的「编码截图」参数连接到第二步的 Base64 编码结果。
2. 关闭快捷指令的「运行时显示」，避免截到快捷指令界面。
3. 首次触发允许快捷指令调用 App。图片编码后直接传入 App，恢复原图后由内置 Vision 识别，不写入相册。
4. 绑定操作按钮或轻点背面；付款、收款、红包、退款后停留在完整详情页再按按钮。
5. 识别后直接入账，无需逐笔确认。需要纠正时打开账目编辑；只有余额不一致或资金账户无法匹配时，才通过异常提示进入核对处理。

短信与按键截图共用解析、去重和新卡登记。识别到银行和新尾号会添加银行卡；只有掩码时不推测完整卡号。手动点击粘贴识别仍可用，App 不会在后台或回到前台时自动读取剪贴板。

## 分类和历史数据

分类分别用于收入和支出。可在我的、记一笔和账目详情分类菜单中添加或删除自定义分类。删除只影响新账目的可选项，不删除历史账目或历史名称。

升级时旧账目默认保持支出，避免无依据地改动旧数据。旧版本已忽略的收款或退款可在「已忽略的资金流动」中重新识别入账。对原始 OCR 文本中确有依据、仅被拆行截断的公司后缀，可恢复完整商户名；不会凭空补写原文缺失的内容。

## 验证边界

原8张微信支出原图由 App 共用的本机 OCR 识别，72项字段全部通过。收入、红包、退款、重复记账、新卡和分类删除/同步使用模拟文本与存储测试；未获得相应真实收入原图。不把这组结果扩展为任意微信/支付宝图片100%准确。

历史版本的自动化方案调研可在 [v1.3.0 文档](https://github.com/callum-albert/7_Bookkeeping/blob/v1.3.0/docs/automatic-bookkeeping.md) 查看；其中实验性识屏不属于当前发布功能。
