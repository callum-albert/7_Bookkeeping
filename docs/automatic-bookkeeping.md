# 微信 / 支付宝自动记账调研与设置

核实日期：2026-11-14。适用范围：普通、非越狱 iPhone，使用公开系统能力。

## 结论与覆盖范围

**本版实现了 iOS 27 的 ScreenCaptureKit 自动识屏会话：先由用户通过系统选择器开启屏幕共享，会话内自动读取成功支付页，不需要每笔按键或截图。** 已加入 `screen-capture` 后台模式、系统权限用途说明、停止入口、锁屏结束处理、稳定画面检测和交易单号去重。此功能已通过 iOS 编译，尚未在真实 iPhone 上完成跨 App 后台验收，不应表述为已经完全无感、长期驻留成功。

没有找到面向普通个人用户、允许第三方 App 订阅微信或支付宝全部消费结果的公开接口。用户未开启识屏会话时，银行消费短信仍是无需每笔按键的数据入口。商户收款 API 不能读取个人在任意商户的消费账单。

| 路线 | 判断 | 原因及限制 |
|---|---|---|
| iOS 27 ScreenCaptureKit → 本机 OCR → 入账 | 已实现授权会话，待真机验收 | 使用官方系统选择器和 `screen-capture` 后台模式，不再需要 ReplayKit 广播扩展；共享状态可见，停止后不会自动重启 |
| 银行短信 → 快捷指令 → 解析文本 | 可配置，全自动入口 | 银行需逐笔发短信，存在金额门槛、延迟、缺商户名；锁屏和授权需真机验证 |
| 银行逐笔消费邮件 | 有条件可用 | 邮件触发存在，但不能假定所有系统版本均把邮件正文传给动作；先验证输入，月账单不能当逐笔通知 |
| 微信 / 支付宝通知监听 | 无公开通用入口 | User Notifications 处理本 App 的通知；通知扩展也不授予读取其他 App 通知的权限 |
| App 关闭时自动截屏 | 不能可靠捕获支付页 | 触发发生在关闭或切离后，截到的可能是桌面或新 App；“关闭”不表示“支付成功” |
| 截屏后退出自动记账 | 已实现，辅助入口 | 用户仍需截屏；新动作仅查相册90秒内的截图，不使用普通照片或旧截图 |
| 旧 ReplayKit 广播扩展 | 本版选用 iOS 27 的 ScreenCaptureKit 替代 | 旧方式需要广播扩展；iOS 27 官方推荐迁移到 ScreenCaptureKit，仍需用户授权及系统共享提示 |
| 钱包 Transaction 触发器 | 不适用于微信 / 支付宝扫码付款 | 官方说明为 Wallet 中所选卡片的轻触交易触发 |
| FinanceKit | 不覆盖中国微信 / 支付宝个人账本 | 当前官方列出的支持范围在美国和英国，并需专门 entitlement 及符合分发条件 |
| 微信 / 支付宝商户账单 API | 不能解决个人全量记账 | 读取签约商户自己的交易；不能跨商户获取个人消费 |
| 网络代理 / VPN 抓支付流量 | 未采用 | 不能假定可解密第三方 TLS 或有稳定可用的个人账单接口，部署成本高且会接触支付敏感数据 |
| 定期导出个人账单 | 适合未来补漏对账 | 不是实时自动触发；本版本未新增账单文件导入，不能把商户 API 代替个人导出 |
| Mac 接收 iPhone 转发通知 → 本机桥接记账 | 可进一步做独立验证，未实现 | Apple 支持将 iPhone 通知转发到 Mac，但这并不授予 iOS App 读取权限；还需验证微信通知内容、Mac 授权、桥接程序和常开设备条件，不能当作已完成能力 |

## 推荐配置

### iOS 27：授权自动识屏会话

1. 在“我的 → 自动记账”打开“自动识屏会话”，点击“开启系统授权识屏”。
2. 在系统选择器中确认共享屏幕。必须共享包含支付 App 的屏幕内容；只采集记账 App 自身看不到微信或支付宝。
3. 切到微信或支付宝正常付款，停留在支付成功页或完整账单详情页数秒。系统采集画面在本机 OCR，两次稳定识别后交给账本入账。没有明确来源的简化成功页可能需要打开账单详情才能识别。
4. 可在 App 中点击“停止识屏”，也可从系统屏幕共享入口停止；系统终止、锁屏或 App 被杀后，需要重新开启，不自动绕过授权恢复。

不会保存视频、不上传画面、不添加音频/麦克风采集输出，不请求摄像头。屏幕共享的实际范围由系统选择器控制，可能覆盖其他 App；非账单文字不会写入账本。单张画面只在内存保留，完整像素摘要缓存避免静止页面重复 OCR；交易单号避免同店同金额的不同消费被合并。

边界：必须 iOS 27+，功能入口在 iOS 26 隐藏，框架弱链接；共享状态可见，持续采集存在耗电。后台模式、用途说明和 SDK API 已接入并通过编译，真实设备的安装签名权限、系统策略、长时间运行和停屏处理仍需实测。SDK 明确包含“缺少 entitlement”的错误；如返回该错误，App 会说明安装签名不支持，不能通过重新点击授权或 ad-hoc 签名绕过。当前仓库没有可供真机验收的开发者证书和设备配置，未擅自添加未经官方确认的权限键。没有声称通过单纯声明后台模式即可无限常驻。

### 绑定银行卡付款：银行短信自动化

1. 先确认银行会向该手机号发送逐笔消费短信，并了解通知门槛。
2. iPhone「快捷指令」→「自动化」→「信息」，选择银行发件号码。
3. 按实际短信设置关键词，如“消费”“支出”“扣款”。多个关键词建议分别建规则，不要只配置“消费”而遗漏其他措辞。
4. 设置“立即运行”，添加“7记账 → 解析账单文本记账”。把收到的信息正文传给“账单文本”；不能仅传发件人。
5. 解锁执行一次完成授权，再用一笔真实消费核对金额、卡尾号及是否新增记录。之后验证锁屏时能否成功。

这是由银行短信驱动，并非直接监听微信。没有短信的消费不会触发；“余额变更”等非消费提醒也不应拿来替代消费短信。

### 零钱 / 余额付款：截屏后退出即记账

1. 在「快捷指令」中先运行一次“用最新截图记账”，完成相册读取授权。完整访问更适合持续读取新截图；有限访问只能读取授权过的图片。
2. 新建「App」自动化，选微信和支付宝，选择“关闭时”“立即运行”。
3. 添加“7记账 → 自动识别刚截的账单”。
4. 每次付款后在成功页或完整账单详情页截屏，90秒内退出支付 App；无需再长按操作按钮或打开记账 App。

此入口不会自己截图。无相册权限时静默跳过，不在后台突然弹授权；没有90秒内的新截图也跳过。锁屏、后台执行权限、照片可见性和截图入库延迟需要真机确认。重复执行交由账本去重；同金额不同商户不会因为“待确认”就合并。

## 本版识别改进与验证边界

- 按文字相对高度聚合视觉行，使用固定行锚点，减少相邻字段被串在一起；右栏换行内容接回对应字段。
- 修正 UIImage 方向、保留截图像素，困难截图使用本机灰度及对比度增强重试。各轮独立解析后择优，金额冲突标待确认。
- 按字段类型限制相邻值：支付方式不能拿商户名，时间不能拿状态栏时钟；兼容值在标签上方的旧 OCR 文本。
- 实付字段优先于顶部金额，缺少主金额时不把优惠金额、卡号或订单号作为消费兜底。
- 商户、商品分别存储，分类只使用商户和商品语义，避免收单机构或页面服务文案污染分类。旧 JSON 无商品字段仍可读取。
- 截图入口不再在失败时读取可能过期的剪贴板；识别到退款直接走忽略流程，不再退回逐行消费解析。

本次额外使用8张真实 HEIC 微信账单原图做了72项人工标注字段验收：金额、分类、来源、账户、支付渠道、支付时间（含秒）、商户、商品、资金流向。8/8图片、72/72字段全部匹配；仅将空白、全半角及等价中点排版归一，不忽略商品编号或下划线。图像管线与 App 复用同一份代码，原图和私人账单报告不提交公开仓库。

验收环境为本机 Apple Vision，不是 iPhone 端到端；不同系统的 Vision 模型可能有差异。样本全部为微信详情页，不能推导支付宝图片准确率。自动分类按可见信息与现有规则验收，无法凭空确定“美团订单”背后具体买了什么；未知分类仍应由用户核对。不要把本组样本全部通过表述成任意账单“OCR 100% 准确”。
