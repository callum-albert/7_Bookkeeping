# v1.5.0 — 账户流转、余额核对与待确认修复

## 修改

- 余额页新增本人账户转账，可选择微信、支付宝或具体银行卡，记录到账金额及手续费。转出扣到账金额加手续费，转入增加到账金额；内部流转不进入收支统计，手续费单独保留在流转记录中。
- 明确微信零钱/支付宝余额提现、充值且具备可定位银行卡、交易单号、不含手续费的文本，可自动调整两端余额。其他转账保留为资金流动待核对，不猜测本人/他人账户和手续费。相同平台单号不重复处理。
- 余额核对以本机首次建立的余额为基准，跟踪之后的账单增删改及本人账户流转。运行期间每分钟、回到前台时检查；短信余额校准或手动改余额造成差异时提示。用户核对真实余额后显式建立新基准。
- 不再把扣款后的负数截成零，避免掩盖漏记、期初余额错误以及删除时虚增余额。
- 修复余额页退出把银行卡余额合计写回第一张卡的问题；仅更新实际修改过的钱包字段，避免覆盖打开转账页期间的新余额。
- 账单 CRUD 统一调整余额：修改金额或资金账户时先还原原账户，再应用新账户；重复删除不会重复退款。
- 待确认弹层独立观察账本，与首页使用同一实时查询，移除按钮嵌套和重复弹窗路径。账目详情默认大弹层，确认操作不再藏在半屏下方。
- 修改分类/商户不再自动取消待确认；提供待核对原因提示以及账户纠正菜单，须显式点「确认这笔」。旧数据未保存精确 OCR 疑点时仅给出一般性核对提示。
- 首页使用惰性布局加载日期分组，减少首次构建大量账目视图的开销。
- 快速记账及 URL 金额校验，拒绝非有限数、负数和过大金额；剪贴板图片/相册读取失败抛出明确错误，不再静默成功。
- 同步快照附带完整银行卡及转账历史；首次恢复时恢复银行卡。余额核对基准是本机状态，非跨设备银行对账服务。

## 后台/冷启动审查结论

短信自动化和操作按钮通过主 App 的 App Intent 执行，入账 JSON 同步原子落盘，不依赖已打开的首页。静态审查没有发现必须先进入首页才能记账的前置条件。

但这不意味着杀后台后始终能执行：

| 场景 | 代码行为与验证边界 |
| --- | --- |
| 打开 App 手动填写 | 保存时落盘；未保存的表单被终止后不保留 |
| 快速记一笔 App Intent | 直接调用统一入账逻辑；无账户参数时仅记收支、不调整余额 |
| 操作按钮编码截图 | 由快捷指令截屏并传入 Base64，Intent 还原图并执行 Vision；不依赖后台剪贴板 |
| 银行短信自动化 | 系统必须收到短信、满足自动化规则并允许立即运行；App 本身不能读取短信收件箱或监听微信通知 |
| 系统回收/用户划掉后 | 由系统决定是否启动 Intent 执行进程；需要签名安装后的真机验收，不能由源码/本机测试保证 |
| 重启后未首次解锁、权限未授权、设备锁屏 | 可能无法访问数据、截屏、相册或运行自动化，需要解锁授权后重试 |
| 定时余额检查 | 仅 App 运行时每分钟，以及启动/前台恢复时；杀后台后不能常驻定时检查 |
| 灵动岛/iCloud | 反馈/备份是尽力而为，不能以灵动岛是否出现判定是否入账；应核对本地账本及执行日志 |

## 真机验收建议

1. 升级前导出备份，设置两张银行卡不同余额，进入余额页不编辑后退出，确认各卡余额不变。
2. 微信 100 元转入银行卡 99.9 元、手续费 0.1 元，确认微信减少 100 元、卡增加 99.9 元，总资产减少 0.1 元，日收支不增加。
3. 进入待确认列表，逐笔改分类和账户，再确认，确认列表和首页计数一致，历史日期账目也可见。
4. 分别在 App 前台、普通后台、系统回收、用户划掉、锁屏状态下触发编码截图和真实短信自动化，核对本地记录、去重、账户余额及设置中的 Intent 日志。
5. 修改真实余额制造差异，返回首页确认出现提示，核对后建立新基准；负余额提示不会因为建立基准而消失，须先修正真实余额/账单。

## 已知边界

- 旧版本缺少历史期初余额及余额流水，不能凭空证明全历史账实相符；首次升级仅建立当前基准。
- 转账不自动匹配「不同平台、不同交易单号」的两端通知。缺少可靠信息时保留待核对，用户处理后应忽略对应事件，避免手工重复操作。
- 无法识别资金账户的账单只计收支，不改余额；信用卡/花呗负债未纳入本次资产余额模型。
- 转账记录暂不提供编辑或删除；录错时可做反向转账，手续费差额需核对真实余额后手动修正。
- JSON 文件各自原子写入，并非跨文件数据库事务；写入错误目前仍沿用旧实现的静默处理。设备在账单和余额文件写入之间终止时可能留下差异，核对基准用于暴露此类情况，不能提供数据库级事务保证。
